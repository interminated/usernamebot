# Username Generator | Game — отдельный Telegram-бот

Это **самостоятельный Node.js-проект** для @UsernameGeneratorGame. Игру, SQL-базу и реферальные начисления он **не заменяет** и **не изменяет**.

## Что умеет

- `/start` — отправляет обложку 640×360, приветственный текст с HTML-оформлением и кнопкой «🎮 Открыть игру»;
- `/help` — показывает справку и кнопку игры;
- `/friends` — объясняет реферальную программу и ведёт в Mini App, где есть вкладка «Друзья»;
- `/start ref_...` — передаёт полученный код в ссылку запуска Mini App `?startapp=ref_...`;
- автоматически добавляет команды Telegram;
- получает сообщения через **long polling** — никакого веб-сервера, порта или домена боту не требуется.

Библиотеки устанавливать не надо: используется стандартный Node.js 22+.

## Установка на BotHost

1. Создай **новый GitHub-репозиторий** для бота (например `username-generator-telegram-bot`), **не поверх репозитория с игрой**. Положи содержимое этой папки прямо в корень репозитория (`bot.js`, `package.json`, `lib/`, `assets/`).
2. Создай **новый Node.js-проект** в BotHost, выбирай **Node.js 22** или новее.
3. **Главный файл — `bot.js`**. Использование домена — **выключено**. Собственный Dockerfile — **выключен**.
4. Добавь переменные окружения:

   ```text
   BOT_TOKEN=секретный_токен_бота_из_BotFather
   BOT_USERNAME=UsernameGeneratorGame
   GAME_URL=https://usernamegame.bothost.tech
   MINI_APP_URL=https://t.me/UsernameGeneratorGame
   ```

5. Свяжи проект с новым GitHub-репозиторием и запусти. В логах ожидается: `Бот @UsernameGeneratorGame запущен (long polling, без HTTP-порта).`
6. Открой @UsernameGeneratorGame в Telegram, отправь `/start` и проверь фото и кнопки.

**Важно: в BotHost при создании двух проектов токен `BOT_TOKEN` может быть одним и тем же:** игра использует его для проверки `initData` Mini App, а отдельный бот — для отправки сообщений. Но только **один** проект должен получать обновления бота (`getUpdates`/`webhook`).

### Если ранее устанавливал патч приветствия в игру

В игровом проекте в BotHost **удали переменную `SERVER_PUBLIC_URL`** (если она добавлялась специально для `/start`) и пересобери игровой проект. В прежнем патче наличие одновременно `BOT_TOKEN` и `SERVER_PUBLIC_URL` вызывало `setWebhook` при запуске игры. Без `SERVER_PUBLIC_URL` эта регистрация отключается. **Не удаляй из игры `BOT_TOKEN` и `MINI_APP_URL`** — они нужны для авторизации и рефералов.

Отдельный бот при запуске делает `deleteWebhook` (без очистки ожидающих сообщений), чтобы перейти на long polling. Если игра позже снова вызовет `setWebhook`, бот перестанет получать сообщения. Поэтому важно, чтобы обработчик webhook **не активировался в игровом проекте**. Если старый патч не устанавливался, ничего в игровом проекте менять не нужно.

### Рефералы

Награда в 100 000 игровых ₽ начисляется **игрой**, а не Telegram-ботом, после первого успешного подтверждённого входа приглашённого игрока через его персональную ссылку. Простое `/start` не начисляет награду. В игре нажми «Друзья» и скопируй ссылку — она должна содержать `?startapp=ref_...`.

### Тесты и локальный запуск

На компьютере с Node.js 22+:

```bash
npm test
```

Для локального запуска создай `.env` из `.env.example`, вставь туда свой токен и выполни:

```bash
node --env-file=.env bot.js
```

Windows: можно запустить `START_WINDOWS.bat` после создания `.env`.

### Если бот не отвечает

- Проверь в логах, что **нет** `409 Conflict: terminated by other getUpdates request` (значит запущено более одной копии polling).
- Проверь `BOT_TOKEN` и `BOT_USERNAME`.
- Проверь, что игра не зарегистрировала webhook после старта бота.
- Не включай «Использовать домен» и не указывай `server.js` для проекта бота: здесь главный файл `bot.js`.

**Безопасность:** токен держи только в переменных окружения или локальном `.env`, не загружай его в GitHub. Если токен попадал на скриншоты, перевыпусти его через BotFather.
